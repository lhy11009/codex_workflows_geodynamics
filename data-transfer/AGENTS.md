# Data transfer workflow

This agent helps construct commands for transferring data between local
and remote systems.

It must never execute data-transfer commands itself.

## Project discovery

Project directories, remote systems, usernames, and other
project-specific configurations must not be hard-coded.

When a transfer involves a modeling project, first locate:

<workspace-root>/.local/PROJECTS.md

Read PROJECTS.md and identify the project requested by the user.

For the requested project:

1. Identify the source machine/configuration.
2. Identify the destination machine/configuration.
3. Retrieve the corresponding project directories and relevant settings.
4. Use the paths and configurations exactly as defined in PROJECTS.md.

If required information is not defined in PROJECTS.md, stop and ask the
user rather than guessing.

## Transfer workflow

For every transfer request:

1. Determine the source machine and source path.
2. Determine the destination machine and destination path.
3. Determine the appropriate transfer method.
4. Construct the command.
5. Return the command to the user.
6. Do not execute the command.

Prefer `rsync` for directory transfers and large or restartable transfers.

## Transfer rules

### ASPECT Simulation Directories (i.e. Cases)

By default, when transferring ASPECT simulation directories, do not transfer
restart files or particle files generated by ASPECT.

Use `rsync --exclude` options to exclude these files from the transfer command.

particle files locates in a subfolder by
`output*/particles`

restart files locates in a subfolder by
`output*/restart`

The exclusions should apply unless the user explicitly requests that restart
files or particle files be transferred.

Do not delete or modify the excluded files at the source or destination.
The exclusions only control which files are included in the generated transfer
command.

## Transfer commands

### Transfer to laptop

A transfer to `laptop` means syncing a case from the `local` project directory
to the laptop.

The generated transfer command should be run on the laptop.

The source `local` project directory must be obtained from
`<workspace-root>/.local/PROJECTS.md`.

The laptop base directory is always:

`/mnt/d/raw_data`

The transferred case directory should be placed directly under this directory.

For example, if the case directory is named `case_1`, the destination should be:

`/mnt/d/raw_data/case_1`

Use the case directory name from the source unless the user explicitly requests
a different destination name.

Apply the ASPECT simulation transfer rules

### Transfer a Specific Step in ASPECT Simulation

A `step` refers to the step number attached to ASPECT visualization output.

The visualization files for a specific step follow the pattern:

`output*/solution/solution-%05d.pvtu` % step
`output*/solution/solution-%05d.*.vtu` % step

When the user specifies a step, include only the visualization `.vtu` files
corresponding to that step.

Use `rsync` include/exclude rules to select the requested visualization step.

This restriction applies only to the visualization `.vtu` files. Still transfer
everything else under the `output*` directory that would normally be transferred
according to the other ASPECT simulation transfer rules.

For example, requesting step `123` selects:

`output*/solution/solution-00123.pvtu`
`output*/solution/solution-00123.*.vtu`

and excludes `.vtu` and `.pvtu` files belonging to other visualization steps.

The normal transfer rules and default ASPECT exclusions still apply.

If the user does not specify a step, do not restrict visualization output by
step.
